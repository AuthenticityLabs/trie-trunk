The U32 control uses the updated codec with the old reference width. It matters: adding the primitive changes compiled enum/match code, and the rebuilt U32 decoder itself became faster on partial and sparse definitions. That improvement cannot be attributed to saving two wire bytes. Against the updated U32 control, REF16 encoding is about 4.6% faster for dense records, 2.0% faster for partial records, and effectively unchanged for the widest sparse case; decoding differs by less than 1%.

What was measured

  • Same Rust process family, same logical values, same preloaded definition/dictionary, same prebuilt input corpus. The first three fields are UUID, shared reference, and mapped text. Other fields rotate through text, bytes, booleans, integer and float scalars; fixtures also include explicit nulls and literal mapped-string fallback. There is no assumed logging schema.
  • PIL encoding uses the existing FrameEncoder::encode_with. PIL decoding uses the existing reusable FrameIndex::scan, then reads typed values from its spans.
  • CBOR uses ciborium-ll 0.2.2 with a benchmark-specific schema-aware flat-map adapter. It is a definite-length numeric-key map, not expanded JSON or an allocated generic value tree. The reader checks field/type bounds, duplicate keys, dictionary references, UTF-8 and exact input boundaries.
  • Both readers fill the same reusable sparse list of borrowed typed values. CBOR walks present keys; PIL scans its mask/definition and span list. Definition parsing, fixture construction, encode preparation for decode tests, warmup and round-trip checks are outside timing.
  • Encoder buffers are reused per event. Decoders borrow strings and bytes. No retained output collection, file I/O, HTTP, compression, index scan, trie expansion, UUID generation, JSON rendering, UI work, or definition negotiation is included.
  • Each invocation warms/calibrates each case, then records seven samples, targeting at least 50 ms per sample where practical. Small collections repeat within a sample; million-event cases run once per sample when already above that duration. There are two invocations per variant, with reordered repeat invocations. This is an interactive host, without CPU affinity or controlled competing load.
  • Round trips are checked against the input and each other for the first 1,024 events, periodic records and the final record, and cross-checked using generic readers outside the timed region. This corpus covers flat scalar values, not nested objects or arrays.

Scope: these are native codec measurements on controlled fixtures, not end-to-end collection throughput or WASM performance. They do not prove that every PIL or CBOR implementation has the same relative performance. In particular, this schema-aware CBOR adapter is not a measurement of Go's generic object marshaller.

Reference changes implemented

  • PIL REF16 is an opaque two-byte little-endian scalar, with normal ABSENT/NULL states and fixed-width array support. Application bindings identify the referenced namespace/version; the primitive is not intrinsically a trie leaf.
  • New server format-4 indexes use U16 leaves: active rows are 34 bytes instead of 36; finalized rows are 26 instead of 28. Population offsets stay U64. Root zero counts toward the 65,536-node cap. At capacity, new path values remain in population at root zero; they are not dropped or wrapped.
  • Trie parents and in-memory lookup ordinals remain U32. Existing format-2/3 data stays readable. Explicit migration creates a separate root and new immutable definition minor, retaining source data and verifying event/population fingerprints.
  • Browser pointers shrink from 44 to 42 packed bytes (28 to 26 bytes after the UUID key), while retaining legacy pointer reads. The browser's existing payload file format remains supported.
  • The current search wire binding still expands shared trie fields into its existing PIL definition. REF16 support does not by itself implement shared-trie replication or redefine existing cached definitions. The benchmark explicitly models a shared reference in both encodings.

Recommendation from these measurements: retain the current CBOR population representation while improving PIL's handling of sparse masks. Caching the definition avoids repeated parsing, but does not remove the current per-record scan of absent positions. Use the faster dense PIL path where applicable; do not assume that replacing all partial CBOR populations with PIL will accelerate them.

Compatibility validation

All Go server/CLI tests, native Rust codec/search tests, 84 browser service tests, production client build, and the real Chromium IndexedDB/OPFS integration suite passed. A separate copy of the 50,000-event demo was migrated into 2,867 format-4 index files. Every UUID and expanded event value matched the old-format search results. The live tap data was not rewritten.
