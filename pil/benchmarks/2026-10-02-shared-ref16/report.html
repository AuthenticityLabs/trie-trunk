Shared fields → REF16

Corrected codec-only comparison · 2 October 2026 · Apple M1 Max · native Rust

Correction: the previous report compared a fabricated U32 reference with REF16. It did not measure replacing shared fields with a trie reference. Its 64/512-field sparse cases also did not represent the intended 8–16-field objects. Those results are not evidence for or against this shared-reference design.

The comparison

Before: all supplied shared fields travel separately, already dictionary-coded.
After: one REF16 identifies exactly that supplied group in a cached trie; dynamic values travel normally. With no shared fields supplied, the reference is ABSENT and contributes no value bytes.

The same executable runs both representations. Definitions, dictionaries, trie data, expanded path caches and reusable buffers are warm before measurement. This avoids both the earlier synthetic U32 field and cross-build compiler effects.

Layout and partial-message semantics

  • The logical definitions contain exactly 8 or 16 fields. This experiment assigns 4 or 8 of those fields to shared groups; that proportion is a stated fixture choice, not a requirement for application schemas.
  • The no-reference PIL Definition contains all 8/16 fields. The REF16 wire Definition compiles the shared slots into one reference slot, leaving 5/9 physical positions. The original object definition and field identities remain cached in the binding. This means some gains come from a shorter field mask/scan, not just reading a two-byte integer.
  • Full objects supply all fields. Each change event supplies exactly 1 or 2 fields total. No hidden UUID or common fields are added to those change payloads; application identity/routing envelopes are outside this codec-only measurement.
  • Dynamic-only changes supply no shared fields, so no REF16 value is sent. Their CBOR bytes remain unchanged; their PIL layout may still have a shorter mask or fewer absent positions to scan. These are layout-compilation effects, not shared-group expansion savings.
  • Shared-field changes reference only the exact 1/2 fields supplied, including groups that skip earlier trie positions. Resolving a reference never fills absent fields from a complete-object snapshot. Small shared groups can cost as much as or more than the fields they replace.
  • Common scalar values are already one-byte dictionary codes in the baseline; no expanded strings or field names are used to inflate its cost. The REF16 replaces the group, not an invented pre-existing reference. CBOR uses numeric field keys in both representations and a numeric reference interpreted through the same cached binding.

Method and limits

  • Existing PIL FrameEncoder::encode_with and FrameIndex::scan; low-level ciborium-ll with a schema-aware flat-map adapter for CBOR. Both encoders reuse buffers. Strings/bytes in decoded output borrow the input; neither side renders JSON or allocates display strings.
  • Input starts from the same preloaded leaf ID plus dynamic typed fields. Both variants have cached per-leaf paths and direct value lookups; neither is charged a repeated trie walk. REF decoding includes a checked lookup in that cache. The after path writes the leaf ID instead of per-field shared values.
  • Ten scenarios × five collection sizes × two representations × two codecs × three operations. Seven warmed samples per condition, repeated with representation/codec order reversed, give 14 samples. Small cases repeat within samples, targeting about 40 ms when practical; medians are reported. The interactive host is not CPU-pinned.
  • Fixtures contain scalar text, bytes, integers, floats, booleans, UUIDs, nulls and absent fields. Every cached path is checked against parent traversal. Round trips check the first 1,024 records, periodic records and the last record, plus every cached group (including root and non-prefix partial groups). Both expanded decoders must reproduce identical logical field sets and values.
  • Definition parsing, trie construction/replication, cache population, fixture creation, correctness checks, file I/O, search, indexing, network, compression, sorting results, JSON and rendering are outside timing. These are codec measurements, not live HTTP or WASM throughput.
  • This is a codec/binding prototype, not a deployment of shared-trie replication in the live collection protocol. The compiled binding for shared slots is explicit benchmark code. Arbitrary inline overrides of shared fields, dictionary/trie negotiation and version rollover still belong to the production binding design and are not benchmarked here.
